# Tilda → 1С bridge

Прокладка между вебхуком формы заказа на Тильде и обменом CommerceML с 1С.

## Как это работает

- `POST /webhook/tilda-order` — сюда Тильда шлёт данные каждой заполненной формы заказа.
  Сервер вытаскивает реальные ФИО/email/телефон/адрес/ИНН/способ оплаты и запоминает их
  по `orderid`.
- `GET/POST /connectors/commerceml/` — сюда обращается 1С вместо `store.tilda.ru`.
  - `type=catalog` — пробрасывается на настоящую Тильду без изменений (каталог и цены
    не трогаем, там всё и так работает).
  - `type=sale&mode=query` — сервер сам забирает настоящий XML заказов у Тильды и точечно
    подменяет в нём блок покупателя на то, что поймал вебхук.
  - всё остальное (`checkauth`, `success`) — пробрасывается на настоящую Тильду как есть.

## Вариант А: через Claude Code (быстрее)

Открой эту папку в VS Code с Claude Code и попроси примерно так:

> Инициализируй здесь git-репозиторий, закоммить все файлы кроме .env и
> node_modules, создай новый репозиторий tilda-1c-bridge на GitHub через gh CLI
> и запушь туда код. Дай ссылку на репозиторий.

Дальше на [render.com](https://render.com) → **New → Blueprint** → выбери этот
репозиторий. Render сам прочитает `render.yaml` и предложит форму, где нужно
будет вписать только 4 значения (без остального ручного конфигурирования):
- `AUTH_USER` — придумай логин
- `AUTH_PASS` — придумай длинный пароль
- `TILDA_USER` — `27122996`
- `TILDA_PASS` — `a1748e42bbaf19430e76d55343232549`

Нажми Apply/Deploy — и всё.

## Вариант Б: руками, без Claude Code

1. Создай **новый пустой репозиторий** на GitHub (например `tilda-1c-bridge`).
2. Залей туда все файлы из этой папки (кнопка "Add file → Upload files" на странице
   репозитория — можно просто перетащить файлы мышкой, без командной строки).
   Файл `.env` заливать не нужно, его и не будет — секреты вводятся в Render отдельно.
3. Зайди на [render.com](https://render.com), зарегистрируйся (можно через GitHub).
4. New → Web Service → выбери свой репозиторий `tilda-1c-bridge`.
5. Настройки сборки: Render должен сам определить Node.js. Если спросит:
   - Build Command: `npm install`
   - Start Command: `npm start`
6. В разделе **Environment** добавь переменные (значения свои, не из .env.example):
   - `AUTH_USER` — придумай логин
   - `AUTH_PASS` — придумай длинный пароль
   - `TILDA_USER` — `27122996`
   - `TILDA_PASS` — `a1748e42bbaf19430e76d55343232549`
7. Нажми Deploy. После завершения сборки Render выдаст адрес вида
   `https://tilda-1c-bridge-xxxx.onrender.com`.
8. Открой этот адрес в браузере — должно показать "Tilda-1C bridge работает".

## Что переключить после деплоя

**В Тильде** (Настройки сайта → Формы → Webhook, там же где вставляли webhook.site):
замени адрес на
```
https://ТВОЙ-АДРЕС.onrender.com/webhook/tilda-order
```

**В 1С** (там же, где раньше стоял `store.tilda.ru/connectors/commerceml/`): замени адрес на
```
https://ТВОЙ-АДРЕС.onrender.com/connectors/commerceml/
```
и впиши логин/пароль — те, что задал в переменных `AUTH_USER` / `AUTH_PASS` на Render
(не обязательно те же, что были для настоящей Тильды).

## Важно про бесплатный тариф Render

Бесплатный инстанс "засыпает" после ~15 минут без запросов и просыпается ~30-50 секунд
при первом обращении. Для нечастых тестовых заказов это не страшно (максимум придёт
чуть позже первого раза), но если станет мешать — можно перевести на минимальный платный
тариф (несколько долларов в месяц) для постоянной работы без "сна".

## Если данные покупателя всё равно не подтянулись

Это ожидаемо для самого первого реального теста. Зайди в Render → твой сервис → вкладка
**Logs**, найди блок `--- RAW XML от Тильды ---` и пришли его мне целиком — там будет видно
точную структуру, которую использует именно ваша 1С, и я поправлю названия тегов в
`xmlPatch.js` под неё.
